# Deadload

Local-first bodyweight training app. Build routines, import LLM-generated ones, log every set. Runs offline as an installed PWA.

> Named for the structural engineering term for a structure's own self-weight. In calisthenics the only load is you.

Single user, no accounts, no backend. Data lives in the browser (IndexedDB) with JSON backup export.

## Status

M0–M3 done. 108 bodyweight exercises with images, routine building, LLM/CSV import with name resolution, five built-in routines, and a session player with per-set logging, rest timer and crash-resume — all offline in a sideloaded Android app. Backup and export (M4) and statistics (M5) are next.

## Install on Android

Download and open **deadload.apk** from the [latest sideload release](https://github.com/Mech-eng-au/Deadload/releases/tag/android-latest) on the phone itself:

```
https://github.com/Mech-eng-au/Deadload/releases/download/android-latest/deadload.apk
```

That link always points at the newest build. Android asks for permission to install unknown apps from your browser the first time; after that it is a normal install. The app needs no network — the exercises and images are inside the APK.

Every build is signed with the same committed sideload key, so a newer APK installs over the old one and keeps your data.

## Development

```sh
npm install
npm run dev            # local dev server
npm run build          # static production build (output in build/)
npm run check          # type check
npm test               # unit tests for the storage layer
npm run build:catalog  # regenerate the catalog from free-exercise-db (network required)
npm run build:apk      # web build + Capacitor sync + signed APK (needs the Android SDK)
```

The APK is normally built by `.github/workflows/android.yml` on GitHub's runners, which have the Android SDK preinstalled.

The catalog (`src/lib/catalog/*.json` and `static/media/`) is generated by `npm run build:catalog` but committed, so the app builds without network access. Deployed to GitHub Pages by `.github/workflows/deploy.yml` on push to `main`.

## Stack

SvelteKit 2 / Svelte 5 (runes), TypeScript strict, Tailwind v4, `@vite-pwa/sveltekit`, static adapter; IndexedDB via `idb` from M1. See the spec for the reasoning.

## Exercise data

The catalog is built at development time from [free-exercise-db](https://github.com/yuhonas/free-exercise-db) (public domain) plus hand-authored entries, and committed to the repo. Every catalog entry has at least one image — that constraint drives the import design.
